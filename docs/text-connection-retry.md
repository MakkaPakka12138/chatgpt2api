# 普通对话连接重试与诊断

普通对话共享协议链路（Chat Completions、Responses 和 Messages）在 curl 5/6
域名解析错误、7 建立连接失败、35 TLS 握手失败时，关闭失败的客户端，等待
1 秒，以原账号创建新连接重试一次。整个调用最多 3 次尝试（包括原有的
登录凭证刷新或账号切换），不会因这类网络错误隔离账号或将额度置零。

重试只允许发生在未输出文字且上游未接受对话的情况下。对话 HTTP 成功后
即标记为已接受，即使尚无文字，也不重新提交。读取超时、连接重置、HTTP
500/429、证书验证错误不属于这次自动重连范围，避免结果不明时重复执行。
TLS 验证保持开启。

代理选择遵守现有设置，代理池关闭时不会擅自切换到其他端口。代理池开启
时保留其已有健康检查和绑定迁移机制；一次 TLS 错误不会直接迁移整批账号。
本次增加的是一次连接重试，没有增加额外的备用代理请求。

每条调用日志带有 `request_id`，管理员详情页增加“连接与重试记录”：

- 每次尝试的账号邮箱或不可逆账号编号、代理来源及无凭据代理地址。
- 首页连接、对话凭证 prepare/finalize、对话提交或接收回复的失败阶段。
- 每步目标地址（不含 query）、HTTP 状态或 curl 错误码、错误类别及耗时。
- 每次尝试的开始/结束时间、首次文字等待时间、重试动作和最终结果。

同一 `request_id` 出现在容器日志的 `text_upstream_attempt` 事件中，方便将
前端记录与服务器日志关联。失败尝试和恢复成功的尝试都保留在最终调用
日志中；前端显示时间继续使用浏览器时区。每次尝试至多记录 16 个 HTTP
步骤，最多 3 次尝试，不记录请求头、Cookie、代理密码、完整账号 token、
对话凭证或 HTTP 请求/响应正文。连接步骤耗时衡量建连至响应头，整个尝试
耗时包含读取回复；两者不能混用。

历史日志没有上述字段，保持原样；只有更新后的新调用有完整诊断记录。
