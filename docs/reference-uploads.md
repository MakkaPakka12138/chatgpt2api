# 参考图上传与额度

ChatGPT Web 生图的上传额度与生图额度分别处理。Codex 图片接口直接提交图片内容，不使用 Web 文件上传额度，账号表中显示“不适用”。

## 一次上传，多次复用

同一账号、相同图片二进制内容会复用已确认上传的文件 ID。文件名和 base64 表达方式不影响命中。并发提交相同参考图时只执行一次上传，其余任务等待该上传完成；失败的上传不写入缓存。

优先选择已缓存全部参考图的可用账号，并保留原有套餐、来源、生图额度和单账号并发限制。文件 ID 不跨账号共享。缓存仅存在于当前服务进程内，最多 512 条、有效期 1 小时；重启或 token 更新后需要重新上传。若上游明确报告文件失效，清理该账号缓存，最多换号重试一次。

开启自动删除对话时，使用参考图的对话会延迟清理。只有它涉及的文件已从缓存过期、移除或淘汰，而且没有生成请求仍持有这些文件，才允许删除对话；纯文生图维持原有清理行为。上传缓存读取和使用计数在同一把锁内执行，避免清理与并发复用之间的竞态。

待清理任务保存在数据目录的 `reference_conversation_cleanup.json`（与账号文件一样包含敏感认证信息，文件权限为仅所有者读写），正常每 5 秒检查一次。清理使用独立连接；网络失败最多尝试 3 次，未完成任务保留，服务重启后再恢复处理。关闭自动删除对话时，不新增清理任务，已有任务继续完成。

上游单次会话可以返回多张图片，原有结果收集行为保持不变。API 显式指定 `n > 1` 时，现有实现仍会执行多次独立生成；同一账号下的参考图可通过缓存复用。

## 上传额度和冷却

账号刷新时，若上游 `limits_progress` 包含可识别的文件上传项目及 `remaining`，保存剩余次数和恢复时间。未提供时显示“未知”，不会推算或假设固定每日限额。已知额度由实际创建文件的调用扣减；缓存命中不扣减，正在创建的文件会预占额度，避免并发任务同时花费最后一次已知额度。

带参考图的生图请求会根据尚未缓存的图片数量筛选账号。需要新上传时，已知剩余次数必须至少为 20，且足够上传本次所有未缓存图片；低于 20 时提前切换到其他可用账号，不回退使用低额度账号。正好 20 次仍可选用。上游未提供余量时仍允许尝试。已缓存全部参考图时，即使新上传额度耗尽，也可尝试使用缓存；纯文生图不受上传冷却影响。并发选号会参考已预占的上传余量；已经选定账号的请求可继续完成本次参考图上传。

文件创建接口明确返回上传上限错误或 HTTP 429 后，账号进入独立的上传冷却状态。优先读取 `Retry-After` 秒数，其次提取错误文本中的分钟数（例如 46 分钟）；均缺失时保守冷却 1 小时。仅设置上传冷却，不禁用账号或清空生图额度。恢复时间到达后旧上传余量失效，变为“未知／待验证”，下一次新上传重新验证。

## 重试

每次独立生成遇到上传上限时，排除失败账号并最多换号重试一次。第二个账号仍失败或没有其他满足条件的账号，则返回上传限额错误，不循环换号。其他网络、鉴权和内容政策错误维持现有处理规则。

带参考图的请求实际命中过上传缓存，并且开始生成的 `/backend-api/f/conversation` 返回空 HTTP 500、尚未输出任何生成事件时，清除本次涉及的文件缓存，最多重新上传重试一次。重试优先使用原账号，但重新验证图片额度和新上传至少 20 次的条件；原账号不再符合条件时才选择其他可用账号。全新上传的 500、非空错误内容、其他接口错误，以及已有输出后的错误不会触发这条补救。日志事件 `reference_upload_cache_retry` 记录原因和重试次数。

前端账号表新增“上传额度”列，显示已知剩余次数、未知状态，或上传受限及预计恢复分钟数。

2026-09-30 真实对照测试复现了：保留对话时一次上传可多次生成；删除所有使用同一参考文件的对话后，复用旧文件编号返回空 500；重新上传恢复。并发使用、缓存过期、容量淘汰、重启恢复、额度复验和重试上限通过单元测试验证。缓存 TTL 不代表上游保证文件在此时间内有效。
